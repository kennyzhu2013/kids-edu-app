## 2. 优先级

这里的 P0 / P1 / P2 是 V1.1 这一程序内部的顺序，不是任务书里把 GamePlugin 和掌握度都标成 P0 的那一版。

### P0（Sprint 1 结束时要为真）

- 七个规划学科和专题编码落在**独立于课程馆 Tab** 的数据里，现有四科入口不变。
- `KnowledgePoint`、专题从属、`KnowledgeDependency`（多对多，无 `parentId`）可写入、可按码查询。
- 现有中文、英语、数学两包、生活认知关卡，以及五款游戏，带上 `knowledgePointIds`。允许一个关卡对应多个知识点。不要求把规划里的每个三级知识点都填满。
- `math-starter` 一包走完：打标、客观步骤服务端计分、跟读仍为设备参考分、夹具仍由现有播放器加载。
- 生产环境没有 `DATABASE_URL` 时拒绝启动或拒绝接口，开发环境无库仍可用。
- 生产环境不接受默认 PIN、默认验证码、默认后台令牌。
- 有一段可展示的隐私与监护人同意说明，并记下同意时间。开发环境不因缺同意而无法打开今日页。

### P1（Sprint 2 和 Sprint 3）

- Sprint 2：薄 `GamePlugin`（React 组件适配，不换引擎）、`LearningEvent`（含 `no_hearing`、错因枚举、幂等、孩子归属校验）、关卡关键步骤上报。异常退出不记完成。
- Sprint 3：规则掌握度（数据不足为「待评估」）、1/3/7/14 天复习且同一天同一知识点不重复有效任务、今日计划改为先复习和薄弱再新知、家长报告分习惯 / 掌握 / 趋势 / 建议，没有数据就显示数据不足。

### P2（本程序不做，只留边界）

- CMS、Phaser、Blockly、CosyVoice 或其它云端 TTS、AI 讲题 / 出题 / 陪练。
- 真实短信、微信、支付、广告、会员商业化（原看板 W5）。
- 应用提审、落地页、原生 `ios/` 与 `android/` 工程（原看板 W8）。
- 把四个功能 Tab 改成七个学科入口。
- 把全部关卡步骤拆成 `Question`。
- 用掌握度模型或大模型直接改分数。

## 3. 增量迁移方案（只描述，不执行）

原则：新迁移目录，不编辑 `20261018120000_init` 和 `20261114160000_progress_state`。不 `prisma migrate reset`，不删行，不改现有关卡主键。开发库用 `prisma migrate dev` 生成迁移；已有环境用 `prisma migrate deploy`。生成迁移的那个 PR 才执行命令，Sprint 0 的仓库里还没有这些文件。

建议分成三次迁移，和 Sprint 对齐，避免空表被提前当成功能已上线。

### 迁移 A（Sprint 1）

新增，全部可空关联或新表，不改 `Progress` 的列语义：

- `CurriculumSubject`：`id`（如 `ZH`、`EN`、`MA`、`SC`、`HL`、`SE`、`AR`）、`name`、`sort`、`status`。**不要**复用 `Subject`，以免 `listSubjects` 多出胶囊。名称用规划第八节：中文启蒙、英语启蒙、数学启蒙、科学探索与认知、健康与生活、社交与情绪、艺术与创造。产品里的「认知」对应科学探索与认知，不另建「认知科学」。
- `CurriculumCourse`：专题。`id` 为 `MA01` 这类编码，`subjectId` 指向 `CurriculumSubject`，`title`、`sort`、`status`。生活数学单独一条，编码在第 6 节选定之前不要插入互相矛盾的两套。
- `KnowledgePoint`：`code` 唯一，`courseId` 表示所属专题（不是前置），`title`、`difficulty`、`status`、`sort`、`version`，`ageTargets` 用 `Json`（键 A/B/C，值是目标说明，允许某年龄段缺省或标成「不作为目标」）。拼音和 20 以内运算可以有行，但 A 段目标不得写成必修。
- `KnowledgeDependency`：`fromId`、`toId`、`relation`（`prerequisite` | `related` | `extension`），三者唯一。不在 `KnowledgePoint` 上加 `parentId`。
- 可选 `KnowledgePointTag` 不需要。步骤上的 id 列表先放在 JSON。若要在 SQL 里按知识点查关卡，再加一张 `LevelKnowledgePoint`（`levelId`、`knowledgePointId`，可加 `stepId` 字符串），由种子从夹具写入。这张表是索引，删了也不影响播放。`levelId` 用现有 `Level.id`，外键 `ON DELETE CASCADE` 可以，但种子不要删除关卡。

`User` 增加可空 `guardianConsentAt DateTime?`。不回填。

不在这次加 `LearningEvent`、`KnowledgeMastery`、`ReviewPlan`、`Question`。`Question` 若数学试点需要稳定主键，可以在迁移 A 末尾加一张只被 `math-starter` 使用的表：`id`、`levelId`、`stepId`、`kind`、`knowledgePointId`、`answerKey Json`。其它课包零行。也可以把试点答案校验直接读夹具而不建表；二选一，不要两套真相。建议：**试点校验读 Zod 解析后的夹具**，`Question` 表延到试点证明字段够用再加，避免 Sprint 1 同时维护 JSON 和表。实施计划把「可选 Question 表」留在 Sprint 1 的验收里：要么有表且只有 `math-starter` 的行，要么明确写「本程不建表，校验读夹具」，不能做成半套。

默认决定（写进 Sprint 1 任务，除非开工时发现夹具字段不够）：**Sprint 1 不建 `Question` 表**，服务端用 `loadPlayableLevels()` 里该步骤的 `answer` / `basket` 校验。这样不会出现第二份答案。

### 迁移 B（Sprint 2）

- `LearningEvent`：`id`、`childId` 外键、`sessionId` 字符串（先不建 `LearningSession` 表，除非上报需要会话级约束）、`type`、`knowledgePointId` 可空、`levelId` 可空、`gameId` 可空、`stepId` 可空、`correct` 可空布尔、`durationMs`、`errorCause` 可空、`source`（`server` | `device`）、`clientEventId` 唯一、`createdAt` 默认 `now()`（库用 UTC）。
- `type` 至少包含：`learning_started`、`lesson_started`、`lesson_completed`、`question_answered`、`question_failed`、`hint_requested`、`game_started`、`game_completed`、`review_completed`、`learning_paused`、`no_hearing`。
- `errorCause` 只允许：`concept_error`、`recognition_error`、`operation_error`、`listening_error`、`attention_error`、`unknown_error`。无法判断就 `unknown_error`，不要用答错推断注意力。
- `no_hearing` 行的 `correct` 为空，不参与错误次数。
- 游戏配额若加幂等，给 `GameQuota` 的消耗另记事件 id，或在 `LearningEvent` 上表达，不要改 `used` 的含义。现有 `used` / `bonus` 列保留。

### 迁移 C（Sprint 3）

- `KnowledgeMastery`：`childId` + `knowledgePointId` 唯一，`score` 可空，`status`（`insufficient` | `not_yet` | `learning` | `basic` | `fluent`），`updatedAt`。样本不够时 `status = insufficient`，`score` 为空，不要写成 0。
- `ReviewPlan`：`childId`、`knowledgePointId`、`dueOn`（日期）、`status`。同一孩子、同一知识点、同一 `dueOn` 唯一，用来挡住「同一天重复的有效任务」。间隔初值 1、3、7、14 天，写在代码常量里，不写进迁移。

掌握度公式用方案里的初始规则 `M = 0.4A + 0.25C + 0.2R + 0.15D`，变量先归一到 0–100。这是工程规则，不是诊断。跟读的设备分可以进入展示，但掌握度计算要能排除 `source = device` 的跟读，或把它们标成不可单独决定档位。单次答错不得把分数打穿一档以上；具体衰减在 Sprint 3 用夹具样例写死并测试，不在本计划里发明第二套公式。

## 4. Sprint 任务

### Sprint 0（本变更）

已完成的定义：审查文档和归档进入仓库，业务代码和 schema 的 diff 为空。没有下一步实现藏在这个分支里。

### Sprint 1：目录、打标、数学试点、安全基线

建议拆成可以分开提交的任务。每一步做完，现有今日 → 听一听 → 点选 → 星星这条路径仍要能走。

1. **编码决定。** 在 `docs/curriculum/` 加一页短的编码说明（或在课程规划文后加附录，不要改归档原文的历史表述）：七个学科码、数学专题最终列表、生活数学的码。决定内容见第 6 节。未写完这一页之前不要把两套 MA08 都种子进库。
2. **迁移 A。** 按第 3 节建规划表和依赖表、`guardianConsentAt`。种子只插入学科和专题骨架，以及**已经能对应到现有关卡**的知识点，不填满 45 个专题下的 5–15 条。
3. **查询 API。** 新的只读接口，例如按学科列专题、按专题列知识点、按知识点列关卡 id。不要改 `GET /api/subjects` 的返回，课程馆继续四科。
4. **打标。** 给 45 个关卡 JSON 和 5 个游戏 JSON **追加** `knowledgePointIds`。Zod 改为可选数组，缺省当 `[]`，这样半成品夹具仍能启动。`math-starter` 必须每关、每道客观步骤都有 id。其它包至少关卡级有 id。游戏按第 7 节的线索挂，颜色配对不要因为名字挂到艺术学科。保留 `knowledgeTags`。
5. **数学客观题校验。** 仅当 `packId === "math-starter"` 且步骤类型是 `tap`、`drag`、`sort`：客户端在完成时附带每步选择（步骤 id + 选择）。`completeLevel` 用夹具答案重算该包的星星和分数；跟读步骤只记录「设备说对了 / 说错了 / 未作答」，不参与重算，也不因为设备分把服务端星星抬高。其它 `packId` 仍走现在的客户端 `score` / `stars`。请求里没有逐步作答时，`math-starter` 返回 400，而不是静默信任客户端（只影响这一包）。
6. **`count-tap`。** 若第 5 步改到 `LevelPlayer` 的分支，让 `count-tap` 复用点选界面。不改 `eng-starter-04.json` 的题目。
7. **生产守卫。** `NODE_ENV === "production"` 且没有 `DATABASE_URL`：进程在接请求前失败，错误信息写明需要数据库，不要创建内存账本。非生产保持现状。
8. **密钥隔离。** 生产环境下，`PARENT_LOCK_PIN`、短信验证码、`ADMIN_TOKEN` 若缺省或等于 `2580` / `000000` / `dev-admin`，对应功能失败并打日志。开发默认值保留，方便现有 README 的内测步骤。家长锁在有库时把哈希写入已有 `pinHash`（实现时选定一种库已依赖的哈希；现在依赖里没有 bcrypt，不要为了 Sprint 1 先引入一套账户系统）。明文不再留在会回写的字段里。开发内存仍可比对明文，与现在一样。
9. **同意说明。** 设置页和引导末尾使用同一段短文：收集昵称、年龄段、学习进度；跟读音频不上传到本应用；演示登录不是正式账号。勾选后 `PATCH` 写入 `guardianConsentAt`。生产引导未同意不能进今日；开发可以跳过。不写注销流程，家长中心那句「注销还是待办」先留着，避免假装做完了。
10. **今日加载。** 给 `todayPlan.findMany` 加上稳定排序，或按 `day` 取今天。行为仍是四科各一关。这是 A10 的最小修复，避免种子数据一多就换题。

Sprint 1 验收：

- 未打标之前能玩的关，打标之后仍能播完并看到星星。
- `math-starter` 点错不能靠伪造的 `stars: 3` 把库里的星星抬高；跟读步不参与这次抬高。
- `GET` 新目录能查出 `math-starter-01` 的知识点，课程馆胶囊仍是四科。
- 生产配置缺少数据库或仍用演示密钥时不能当作正常启动。
- `eng-starter`、`lang-starter`、`life-starter`、`math-life` 的完成接口仍接受原来的请求体。

### Sprint 2：薄插件与学习事件

1. 定义 TypeScript 类型 `GamePlugin`，只包生命周期：`init`、`start`、`pause`、`resume`、`submit`、`getResult`、`destroy`。五个现有组件仍负责规则。`GamePlayer` 改成查表而不是一串 `if`。暂停可以先等于离开页面时 `destroy` 不计完成，不要求做游戏内暂停按钮。
2. `GameResult` 含 `completed` 布尔。关闭（`onExit`）和未 `submit` 的卸载都是未完成。超时是未完成或失败，**不再**调用现在这种「一律 `onFinish` 就扣次并看起来像赢过」的路径而不加区分。扣次规则要写清楚并保持「会员不扣」：建议仍是「开局成功进入 `play` 后结束（含超时）扣一次」，但事件类型用 `game_completed` 只表示达成胜利条件。这是行为澄清，提交里要写明和旧的「超时也 `onFinish`」差在事件，不差在多扣或少扣，除非产品要改扣次。默认：**扣次时机不变，事件的完成位按是否赢**。
3. 迁移 B。写入要校验孩子属于当前用户（现在只有 `user-demo`，仍要走 `ownChild` 那种明确 404，禁止 `currentChild` 的静默回落）。
4. 幂等：同一 `clientEventId` 第二次返回已存在行，不增加配额、不追加第二行。用数据库唯一约束，不只查内存。
5. 关卡播放器上报：进入关卡、每步作答或失败、提示、跟读空听（`no_hearing`）、关卡完成、离开（`learning_paused`，不是完成）。空听不加 `mistakes`。
6. 页面关掉时先把未发送事件放在 `localStorage` 队列，下次打开再补。队列上限要有，避免无限增长。不上传音频。

验收：重复提交同一事件 id 不重复计数；杀进程再打开不把半局记成 `game_completed`；空听在事件表里能查到且星星不变。

### Sprint 3：掌握度、复习、今日、报告

1. 迁移 C。用规则计算掌握度。样本阈值在实现时写成常量并在文档里记下；低于阈值则 `insufficient`，报告写「数据不足」，不写「未掌握」。
2. 跟读设备分不单独把档位打到「熟练」。客观题的服务端结果才进入 A/C/D。复习表现 R 在有复习事件之前视为数据不足的一部分，而不是 0 分。
3. 错题来自 `question_failed`，不是来自 `no_hearing`。生成复习任务：间隔 1/3/7/14 天，同一孩子同一知识点同一天只一条有效任务。
4. 改 `getToday`：先复习和薄弱，再未学知识点，最后才是兴趣游戏位（游戏位可以仍是入口而不是强制）。每日条数可配置，默认不要多于现在的 4 条。未完成不出现惩罚文案。年龄段 A 仍然不把 `math-life` 塞进必做。
5. 修日历：库存 UTC，`day` 用补零的日期。读旧的不补零配额时做一次兼容解析，避免上线当天次数清零。这是 A11。
6. 报告页区分孩子可见的一句鼓励，和家长可见的习惯、掌握、趋势、建议。没有事件就空状态，不生成建议段落。现有 `weakAreaTip` 可以留在数据不足时当过渡，但不要把它叫做掌握度。

验收：学习 → 有足够客观题 → 出现非「待评估」的档位 → 生成复习 → 今日能看到 → 家长报告与孩子页用词不同。数据不足的新孩子不会看到「未掌握」。

## 7. 生活数学编码（Sprint 1 必须先定，建议如下）

规划归档里，分领域表是 **MA08 时间认知** 加 **MA09 生活数学**（数学会变成 9 个专题，总数约 46）。示例树把二者并成 **MA08 时间与生活数学**，并写数学为 8 个专题。

源码不支持合并成一个专题后再对应一个课包：

- `math-life` 的五关是分水果、买东西、排队几号、几点钟整点、整理玩具。只有「几点钟整点」（`math-life-04`）明显是时间。
- `math-starter` 没有生活应用这五关。
- 今日任务用包 id 把 `math-life` 排除在年龄段 A 之外。合并专题不会去掉这个产品规则，还容易让人把整包都标成「时间」。

**建议：生活数学继续作为单独专题，不并进时间认知。** 编码在 Sprint 1 任务 1 写死，全库只用一套。推荐：

- `MA08` 仍叫时间认知。现有内容里先只把 `math-life-04` 映射到它的知识点。
- `MA09` 叫生活数学，映射 `math-life` 的另外四关。
- 接受数学专题数因此是 9、规划总数约 46，而不是示例树里的 8 和 45。

若希望对外材料仍写「约 45 个专题」，可以在编码说明里把 45 标成不含生活数学单列之前的概数，但数据库编码不要把 `math-life` 塞进 `MA08`。

`math-starter` 按关打到多个专题（数、数量、图形等），不新增一个叫「数感启蒙」的重复专题去和 MA 编码平行。包名可以继续叫数感启蒙，那是 `Pack.title`，不是 `CurriculumCourse`。
